# Agent Workflow Rules & Guidelines

## Pre-Implementation Workflow
Before making any code changes or implementation, always adhere to the following rules:

1. **Analyze Existing Code**:
   - Thoroughly analyze the existing code and understand all related logic and architecture before proposing changes.

2. **Provide Implementation Plan**:
   - Detail the proposed plan first, explicitly enumerating which files will be modified and what will change in each file.

3. **Strict Scope Discipline**:
   - Do not touch unrelated files, logic, or dependencies.
   - Do not refactor or alter existing behavior unnecessarily.

4. **Responsive Design**:
   - Ensure all frontend / visual implementations fully support both mobile and desktop viewports.

5. **Mandatory Confirmation Gate**:
   - **STOP** after providing the analysis and plan.
   - Ask for explicit user confirmation before touching or modifying any files.
   - Only execute the implementation after the user has explicitly confirmed.

6. **Dual-Level Explanations**:
   - Clearly explain the problem, root cause/reason, and solution in two distinct sections:
     - **Human-Readable Format**: Plain, intuitive explanation for quick understanding.
     - **Developer-Level Format**: Technical breakdown covering architectural, logic, and code-level details.
